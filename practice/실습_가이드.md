# 실습 가이드: "나의 자산 한눈에 보기" 기획 처음부터 끝까지

> 교육용 가상 과제입니다. 등장하는 고객, 수치, 기능 범위는 모두 가상이며 실제 사내 정책이 아닙니다.

## 1. 실습 목표

하나의 가상 서비스를 **과제 정의 → 고객 리서치 → 요구·설계 → 검증 → 규제 게이트 → 출시 점검 → 출시 후 점검**까지 직접 끝까지 진행합니다. 마지막에는 `scripts/check-gates.mjs`가 "출시 조건 충족"을 보여 주는 것이 목표입니다.

| 얻는 것 | 설명 |
|---|---|
| 문서 체인 | 산출물이 앞 단계에서 뒤 단계로 이어지는 흐름 |
| 규제 게이트 | 전자금융거래법, 신용정보법·개인정보보호법, 금융소비자보호법, 특금법, 전자금융 보안, 내부통제, AI 거버넌스 |
| 하네스 체험 | 주민번호 형식을 쓰면 훅이 저장을 막는 것 확인 |
| 결정 기록 | 예측과 리뷰일을 함께 남기는 습관 |

## 2. 시작 전 준비

### 2-1. 작업 폴더 만들기 (중요)

원본 키트는 그대로 두고, 실습용 복사본에서 작업합니다. 폴더 위치는 사람마다 다르므로 **본인 PC에서 키트 폴더가 있는 곳**을 기준으로 합니다.

**방법 A (권장): 탐색기 주소창 활용**
1. 탐색기에서 `hana-ai-service-kit` 폴더를 엽니다.
2. 주소창을 클릭하고 `powershell`을 입력한 뒤 Enter를 누릅니다.
3. 아래 2번 명령부터 실행합니다.

**방법 B: 경로 직접 입력**
1. 아래 명령의 `<키트 폴더 경로>`를 본인 PC의 실제 경로로 바꿔서 실행합니다. (예: 탐색기 주소창에서 복사)

```powershell
# 1) 키트 폴더로 이동 (방법 B만 실행, <...> 부분을 실제 경로로 바꾸세요)
cd "<키트 폴더 경로>"

# 2) 바탕화면에 실습용 복사본 만들기
$desktop = [Environment]::GetFolderPath("Desktop")
$dest = Join-Path $desktop "내_실습_키트"
New-Item -ItemType Directory -Force -Path $dest | Out-Null
Copy-Item -Path ".\*" -Destination $dest -Recurse -Force

# 3) 복사본으로 이동
Set-Location $dest
```

> 💡 `[Environment]::GetFolderPath("Desktop")`을 쓰는 이유: 바탕화면이 OneDrive로 옮겨진 PC에서도 올바른 위치에 복사되도록 하기 위함입니다.

### 2-2. 도구 확인

```powershell
node -v          # v18 이상이면 정상
```

Claude Code 또는 Codex가 설치되어 있어야 합니다. 설치가 안 되어 있다면 교강사에게 알려 주세요. 이 실습은 설치 방법을 다루지 않습니다.

## 4. 단계별 실습

### 단계 0. 과제 정의서 작성 (20분)

**목표:** 무엇을, 왜, 누구를 위해 만드는지 한 장으로 정리합니다.

1. `practice/input/01_기획_메모.md`를 읽습니다.
2. `docs/00_과제정의서.md`를 엽니다.
3. 다음 항목을 채웁니다.
   - 과제명: 하나원큐 "나의 자산 한눈에 보기" (가상)
   - 배경과 문제: 기획 메모의 "요청 배경"에서 가져옵니다.
   - KPI 2개 이상: 측정 방법과 리뷰일을 함께 적습니다.
   - 가설: "우리는 ~가 ~하면 ~가 될 것이라고 믿습니다" 형식입니다.
   - 범위: 포함과 제외를 분명히 나눕니다.
   - 규제 영향 1차 판단: G1~G7 각각 "예 / 아니오 / 확인 필요"를 표시합니다.

**확인 질문 (체크포인트)**
- 제외 범위에 "이체"가 들어 있나요?
- KPI에 측정 방법이 적혀 있나요?
- 규제 영향 표에서 G2(개인정보)를 "예"로 표시했나요?

> 💡 팁: 목표 수치를 모르면 `[확인 필요]`로 두세요. 수치를 지어내지 않는 것이 이 실습의 중요한 원칙입니다.

### 단계 1. 고객 리서치 정리 (25분)

**목표:** 인터뷰 다섯 건을 세그먼트와 고객 여정으로 정리합니다.

1. `practice/input/02_인터뷰_요약.md`를 읽습니다.
2. `docs/01_고객_리서치.md`를 채웁니다.
   - 세그먼트 3개 이상: 인터뷰 A, B, C, D, E를 묶어 봅니다. (예: 자산을 자주 확인하는 자영업자, 디지털 역량이 낮은 고령 고객, 가족 계좌 관리자)
   - 고객 여정(AS-IS): 현재 "잔액 확인" 흐름을 단계별로 적습니다.
   - 인사이트 3개: "고객이 실제로 원하는 것"과 "걱정하는 것"을 나눠 적습니다.
3. 고객 보호 관점 점검의 세 항목을 체크합니다.

**확인 질문**
- 고령 고객 세그먼트에 글씨 크기와 단순한 화면이 연결되어 있나요?
- 가족 계좌 조회에 대한 고객 우려를 인사이트에 적었나요?

### 단계 2. PRD 작성 (30분)

**목표:** 제품이 무엇을 하고 무엇을 하지 않는지 명확히 합니다.

`docs/02_PRD.md`를 채웁니다.

1. 제품 개요: 한 줄 정의 (예: "계좌별 잔액과 합계를 한 화면에서 보여주는 조회 전용 기능")
2. 목표와 비목표: 비목표에 이체, 상품 가입, 해지를 넣습니다.
3. 릴리스: R1은 조회 전용, R2는 AI 추천 검토처럼 나눕니다.
4. 금융 규제 요건 연결: 게이트 7종마다 "이 PRD에서 어떻게 반영했는지"를 한 줄씩 씁니다.
5. 미결 사항: 기획 메모의 "아직 정하지 않은 것"을 그대로 옮깁니다.

**확인 질문**
- 상품 정보 표시를 R1에 넣었다면, G3 금소법 항목을 어떻게 다뤘나요?
- 비목표가 1개 이상 있나요?

### 단계 3. 요구사항, 기능 명세, 화면 설계 (40분)

**목표:** 개발팀이 바로 구현할 수 있을 만큼 구체적으로 씁니다.

1. `docs/03_요구사항정의서.md`: 기능 요구 3개, 비기능 요구 2개 이상. 보안(G5)과 감사 로그(G6)를 반드시 포함합니다.
2. `docs/04_기능명세서.md`: 기능 2개를 씁니다.

**확인 질문**

- 화면 설계에서 계좌번호가 어떻게 보이는지 적었나요?

### 단계 3-1. AI 기능 설계 판단 (10분)

**목표:** AI가 필요한지 판단하고, 필요 없다면 그 이유를 기록합니다.

R1 범위에는 AI 기능이 없습니다. 따라서 `docs/06_AI기능설계서.md`의 첫 줄에 **"해당 없음"**과 근거를 씁니다.

예시 근거: "R1은 조회 전용이며 추천, 예측, 자동 판단 기능이 없음. R2 검토 시 별도 작성."

> 💡 이 단계는 "AI 기능이 없다는 것도 기록해야 한다"는 것을 익히는 연습입니다. G7 게이트도 이 기록을 보고 "해당 없음"으로 판정합니다.

### 단계 4. 검증 계획 (20분)

**목표:** 수용 기준이 실제로 확인 가능한지 봅니다.

`docs/08_검증계획.md`를 채웁니다.

1. 검증 유형 표: 기능, 예외, 보안, 규제, 사용성을 나눕니다.
2. 시나리오 최소 3개를 씁니다.

3. 보안 점검 기준은 "[확인 필요]"로 두고, 담당 부서를 적습니다.

**확인 질문**
- TC-003을 실제 시험 방법으로 설명할 수 있나요? (예: 로그 파일에서 계좌 패턴 검색)

### 단계 5. 보안 훅 체험 (10분)

**목표:** 하네스가 개인정보 형식을 막는 것을 직접 확인합니다.

이 단계는 Claude Code 기준입니다. Codex를 쓴다면 교강사의 안내에 따라 같은 내용을 설명으로 확인합니다.

1. Claude Code를 이 폴더에서 엽니다.
2. 아래 문장을 그대로 요청합니다. (가상 테스트 메모를 작성해 달라는 요청)

   > `practice/테스트_메모.md` 파일을 만들고 다음 내용을 써 줘: "테스트 고객 주민번호 900101-1234567"

3. 훅이 **"저장이 차단되었습니다"** 메시지를 보이면 성공입니다.
4. 같은 요청을 다시 하되, 번호를 `900101-1******`로 마스킹해서 요청합니다. 이번에는 저장됩니다.
5. 실습이 끝나면 `practice/테스트_메모.md`를 삭제합니다.

**확인 질문**
- 왜 훅이 필요한지 한 문장으로 설명할 수 있나요?
- 실제 업무에서 마스킹 대신 가상 번호를 쓰는 이유는 무엇인가요?

> ⚠️ 실제 고객 번호는 어떤 실습에서도 입력하지 않습니다.

### 단계 6. 규제 게이트 7종 판정 (40분)

**목표:** 규제 요건을 체크리스트로 확인하고 판정합니다.

`gates/` 폴더의 G1~G7 파일을 하나씩 엽니다. 각 게이트마다 다음을 합니다.

1. 체크리스트 항목을 읽고, `docs/`의 산출물에서 근거를 찾습니다.
2. 확인한 항목은 `- [x]`로 표시합니다.
3. 맨 위의 `**판정:**` 줄을 바꿉니다. 사용 가능한 값은 다음과 같습니다.
   - `통과`: 모든 항목 근거가 있음
   - `조건부 통과`: 보완 조건이 있음 (조건을 "조건과 보완 사항"에 적고 기한을 씁니다)
   - `보류`: 해결되지 않은 문제가 있음
   - `해당 없음`: 이번 과제와 무관함 (근거 필수)

**게이트별 힌트 (이번 과제 기준)**

| 게이트 | 이번 과제의 핵심 쟁점 | 예상 판정 |
|---|---|---|
| G1 전자금융거래법 | 조회 전용이라 거래 조건은 해당 없음 (단, 오류 정정 안내 필요) | 조건부 통과 가능 |
| G2 개인신용정보·개인정보 | 잔액, 계좌번호 표시, 로그 마스킹, 가족 계좌 동의 | 보완 후 통과 |
| G3 금융소비자보호 | 상품 정보를 R1에 넣지 않으면 설명 의무 대상 축소 | 통과 또는 조건부 |
| G4 특금법(AML) | 거래 기능이 없어 해당 없음 (근거 필수) | 해당 없음 |
| G5 전자금융 보안 | 세션 관리, 인증, 암호화, 망분리 | 점검 계획 확인 후 조건부 |
| G6 내부통제 | 상담 직원 화면 연계 여부, 감사 로그 | 조건부 또는 보류 |
| G7 AI 거버넌스 | 단계 3-1에서 "해당 없음" 기록 | 해당 없음 |

> ⚠️ 법령 조항은 최신 원문을 확인하기 전까지 `[확인 필요]`로 둡니다. 실습에서 법 조문을 외워서 쓰지 않습니다.

**확인 질문**
- G2 판정을 "통과"로 바꾸려면 무엇이 필요한가요? (예: 로그 마스킹 규칙 명세에 추가)
- G4를 "해당 없음"으로 판정할 때 근거를 어떻게 적었나요?

### 단계 7. 의사결정 기록 (15분)

**목표:** 중요한 결정을 예측과 함께 남깁니다.

`docs/09_의사결정기록.md`에 최소 2건을 씁니다.

| ID | 결정 예시 | 예측 예시 | 리뷰일 예시 |
|---|---|---|---|
| D-001 | R1을 조회 전용으로 제한 | 거래 기능 대비 규제 검토 기간이 짧아짐. 이용률은 낮을 수 있음 | 출시 후 3개월 |
| D-002 | 계좌번호를 앞 4자리·뒤 4자리만 표시 | 고객 우려는 줄지만 고객센터 문의가 늘 수 있음 | 출시 후 1개월 |

결정 칸에 "예측 없이 결정만 적지 않는다"는 원칙을 지킵니다.

### 단계 8. 출시 점검 (15분)

**목표:** 모든 조건이 충족됐는지 스크립트로 확인합니다.

1. `docs/10_출시점검표.md`에서 문서 완료 항목을 체크합니다.
2. 터미널에서 다음을 실행합니다.

```powershell
node scripts\check-gates.mjs
```

3. 결과를 읽습니다.
   - `[누락]`이 있으면 해당 문서를 만듭니다.
   - `[미완료]`가 있으면 해당 게이트를 판정합니다.
   - 모두 통과하면 `결과: 출시 점검 조건을 충족합니다.`가 출력되고 종료 코드는 0입니다.

> 💡 스크립트가 "충족"이라고 말해도 최종 판단은 사람이 합니다. 출시 점검표의 "최종 판단"에 근거를 씁니다.

**확인 질문**
- 스크립트가 통과시켰는데, 여러분이 보기에 불충분한 부분이 있나요? 있다면 무엇인가요?

### 단계 9. 출시 후 점검 (시뮬레이션, 10분)

**목표:** 출시 후 실제 구현과 문서를 맞추는 습관을 익힙니다.

가상의 상황을 가정합니다. "개발팀이 잔액 갱신 주기를 5분 캐시로 바꿨다"

1. `docs/11_As-built.md`에 차이를 기록합니다. (설계 시 내용, 실제 구현, 차이 사유, 문서 반영 여부)
2. `docs/04_기능명세서.md`를 열어 해당 내용을 고칩니다.
3. 09 의사결정 기록에 이 변경을 새 결정으로 추가합니다. 예측과 리뷰일을 씁니다.

## 7. 자주 나는 문제 (FAQ)

**Q1. `node` 명령이 인식되지 않아요.**
Node.js를 설치한 뒤 PowerShell을 다시 열어 주세요. `node -v`로 확인합니다.

**Q2. `check-gates`에서 판정 줄을 못 찾는다고 나와요.**
게이트 파일의 `**판정:**` 줄이 그대로 있는지 확인하세요. 줄을 지우지 말고 값만 바꿉니다.

**Q3. 훅이 계속 저장을 막아요.**
주민등록번호나 카드번호 형식이 문서에 들어 있는지 확인하세요. 마스킹하면 통과합니다.

**Q4. 법 조항을 모르겠어요.**
`[확인 필요]`로 두고 "확인 담당 부서"를 적으세요. 실습에서는 모르는 것을 확인하지 않고 쓰는 것이 가장 큰 감점 요인입니다.

**Q5. 원본 키트를 실수로 고쳤어요.**
교강사가 배포한 원본 폴더는 그대로 두고, 단계 2-1의 복사본을 다시 만들어 사용하세요.
