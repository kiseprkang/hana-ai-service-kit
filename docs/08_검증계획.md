# 08. 검증 계획

검증은 "무엇을 기준으로 합격인지"를 먼저 정하고, 그 기준을 시나리오로 확인하는 순서로 씁니다.

## 1. 기준점 (합격을 판단하는 기준)
| 기준 구분 | 기준 출처 | 예시 | 기준값 |
|---|---|---|---|
| 기능 기준 | `04_기능명세서`의 수용 기준 | 잔액이 계좌별로 표시된다 | 수용 기준 전체 통과 |
| 성능·보안·감사 기준 | `03_요구사항정의서`의 비기능 요구 (NFR-ID) | 응답 시간, 암호화, 감사 로그 | [확인 필요] |
| 규제 기준 | `gates/` 체크리스트 (G1~G7) | 설명 의무, 동의, 마스킹 | 해당 항목 전체 확인 |
| 사업 기준 | `00_과제정의서`의 KPI | 이용률, 문의 건수 | 목표값 달성 |

> 기준값을 모르면 [확인 필요]로 두고, 담당 부서와 확인할 날짜를 적습니다.

## 2. 검증 범위와 방법
| 검증 유형 | 대상 | 방법 | 담당 | 통과 기준 |
|---|---|---|---|---|
| 기능 테스트 | REQ, 수용 기준 | 수용 기준 기반 시나리오 실행 | | 시나리오 100% 통과 |
| 예외 테스트 | 04 예외 흐름 | 네트워크 오류, 세션 만료 상황 재현 | | |
| 보안 점검 | NFR-보안, G5 | 취약점 점검, 모의해킹 | 보안팀 | [확인 필요] |
| 규제 점검 | G1~G3, G6 | 체크리스트 대조 | 준법 | 전 항목 통과 |
| 사용성 | 고령·취약 고객 | 사용성 테스트 (큰 글씨, 단순 흐름) | | |
| 파일럿 | 일부 고객 | 단계 출시 후 KPI 확인 | | 정한 KPI 달성 |

## 3. 시나리오 목록
각 시나리오는 반드시 연결 ID(REQ, NFR, 수용 기준, G)를 하나 이상 적습니다.

| ID | 시나리오 | 기대 결과 | 연결 ID | 결과 |
|---|---|---|---|---|

## 4. 추적성 확인
- `03_요구사항정의서`의 모든 REQ, NFR이 위 시나리오의 연결 ID에 한 번 이상 나타나야 합니다.
- 확인 명령: `node scripts/check-traceability.mjs`

## 5. 결함 관리
- 심각도 기준: 치명 / 중대 / 경미
- 치명 결함은 출시를 막습니다.
- 결함은 `08` 시나리오 ID와 연결해서 기록합니다.
