# 하나원큐 AI 서비스 기획 키트 (수업용)

AI 도구(Claude Code 또는 Codex)와 함께 서비스 기획 문서를 만들고, 금융 규제 검토까지 한 번 끝까지 해 보기 위한 **수업용 실습 키트**입니다.

> 모든 고객, 수치, 기능은 교육용 가상 자료입니다. 공식 사내 표준이 아니며, 법령과 사내 기준은 담당 부서 확인이 필요합니다.

## 처음 시작하기 (5분)

1. **Node.js 설치** (v18 이상). PowerShell에서 `node -v`로 확인합니다.
2. **이 폴더 열기.** 탐색기 주소창에 `powershell`을 입력하면 이 폴더에서 바로 터미널이 열립니다.
3. **AI 도구 실행.** Claude Code를 쓴다면 `claude`, Codex를 쓴다면 `codex`를 입력합니다.
4. **첫 명령.** Claude Code에서 `/start-service`를 입력하면 과제 정의부터 안내받습니다.

처음 해 보는 분은 [practice/실습_가이드.md](practice/실습_가이드.md)를 그대로 따라가세요. 실습에 필요한 자료는 `practice/input/`에 있습니다.

## 폴더 구조

```
hana-ai-service-kit/
├── AGENTS.md          # AI 에이전트 공통 규칙 (Codex, Claude Code 모두 읽음)
├── CLAUDE.md          # Claude Code 설정 (AGENTS.md를 가져옴)
├── docs/              # 산출물 문서 11종 (여러분이 채우는 곳)
├── gates/             # 규제 검토 게이트 7종 (판정하는 곳)
├── practice/          # 실습 가이드와 가상 입력 자료
├── scripts/           # 점검 스크립트
├── templates/         # 같은 문서의 Word, Excel, PowerPoint 양식
├── tools/             # 템플릿 생성 스크립트 (교강사용)
├── company-materials/ # 사내 자료를 넣는 자리 (Git에 올라가지 않음)
└── .claude/           # Claude Code 훅과 명령 설정
```

## 용어 한눈에 보기

| 용어 | 쉬운 뜻 |
|---|---|
| 에이전트 | 파일을 읽고 쓰며 함께 작업하는 AI |
| 하네스 | AI가 지켜야 할 규칙과 자동 점검 장치를 묶은 것 (이 키트 전체) |
| 산출물 | 과제 정의서, PRD처럼 만들어 내는 문서 |
| 게이트 | 출시 전에 통과해야 하는 규제 검토 단계 (G1~G7) |
| 훅 | 파일을 저장하기 전에 자동으로 확인하는 장치 |
| 수용 기준 | "이렇게 되면 완성"이라고 말할 수 있는 확인 조건 |
| 가상 자료 | 실습용으로 만든 지어낸 데이터. 실제 고객 정보가 아님 |

## 무엇을 먼저 해야 하나

모든 문서를 한 번에 채울 필요는 없습니다. 아래 순서로 시작하세요.

| 우선순위 | 문서 | 이유 |
|---|---|---|
| 필수 | 00 과제 정의서, 02 PRD | 무엇을 왜 만드는지 정합니다 |
| 필수 | 03 요구사항, 04 기능 명세 | 개발자가 읽을 기준입니다 |
| 필수 | 08 검증 계획 | 완성을 어떻게 확인할지 정합니다 |
| 필수 | gates/ G1~G7 | 출시 전 규제 확인입니다 |
| 필수 | 09 결정 기록, 10 출시 점검 | 결정 근거와 최종 점검입니다 |
| 상황에 따라 | 01 고객 리서치, 05 화면, 06 AI, 07 업무 프로세스, 11 As-built | 해당할 때만 채웁니다 |

## 문서 체인 (순서)

```
00 과제 정의 → 01 고객 리서치 → 02 PRD → 03 요구사항 → 04 기능 명세 → 05 화면 설계
      → (06 AI 설계, 07 업무 프로세스: 해당할 때만)
      → 08 검증 계획 → 게이트 G1~G7 → 10 출시 점검 → 11 As-built (출시 후)
결정은 언제든 09 의사결정 기록에 예측과 리뷰일을 함께 남깁니다.
```

## 점검 명령

```powershell
node scripts\check-gates.mjs          # 필수 문서 누락과 게이트 판정 확인
node scripts\check-traceability.mjs   # 요구사항(REQ, NFR)이 검증 계획에 빠짐없이 연결됐는지 확인
```

두 명령 모두 통과해야 출시 점검이 끝난 것입니다. 통과해도 최종 판단은 사람이 합니다.

## 템플릿 파일 (Word, Excel, PowerPoint)

`templates/` 폴더에는 같은 산출물을 Word, Excel, PowerPoint로 옮긴 양식이 있습니다. 문서를 Markdown으로 쓰다가 보고용으로 옮길 때 사용하세요. 자세한 매핑은 [templates/README.md](templates/README.md)를 보세요.

## 사내 자료 넣기

`company-materials/`에 규정이나 사내 템플릿을 넣으면 AI가 사내 기준으로 참고합니다. 이 폴더의 파일은 Git에 올라가지 않습니다. 자세한 구분은 [company-materials/README.md](company-materials/README.md)에 있습니다.

## 보안 기본 규칙

- 주민등록번호, 카드번호 형식이 들어간 파일은 훅이 저장을 막습니다.
- 예시를 쓸 때는 `900101-1******`처럼 마스킹합니다.
- 법령 조항은 확인하지 않은 경우 `[확인 필요]`로 표시합니다.
- 실제 고객 정보와 내부 기밀은 이 키트에 넣지 않습니다.
